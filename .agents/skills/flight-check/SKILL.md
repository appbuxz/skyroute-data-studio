# Flight Check

Вызов: `$flight-check CDG → NQZ, 2027-03-08 ±1 день, 2 взрослых, Economy, личная вещь; без ручной клади и сдаваемого багажа; 194170 KZT за всех или ссылка`.

Принимай маршрут, дату (по умолчанию также день до и после), пассажиров, класс, багаж и исходную цену с валютой либо ссылку. Критичные недостающие параметры уточни. Неизвестный год отмечай предположительным. Различай взрослых/детей, цену за одного/за всех, личную вещь/ручную кладь/сдаваемый багаж и неизвестное/отсутствующее. При расхождении ссылки с явными параметрами пользователя сохрани параметры и сообщи расхождение.

## Поиск

Работай из корня репозитория, прочитай актуальные `docs/travelport-local-development.md`, `docs/flight-check.md`, `src/lib/flights/types.ts`. Предпочти штатную CLI-команду, если она появилась. Иначе используй существующий серверный FlightDataProvider через [scripts/search.mjs](scripts/search.mjs):

```sh
node .agents/skills/flight-check/scripts/search.mjs /tmp/flight-check-input.json
```

Вход — JSON-массив запросов, исходная дата первой:

```json
[
  {"origin":"CDG","destination":"NQZ","departureDate":"2027-03-08","passengers":2,"cabinClass":"economy"},
  {"origin":"CDG","destination":"NQZ","departureDate":"2027-03-07","passengers":2,"cabinClass":"economy"},
  {"origin":"CDG","destination":"NQZ","departureDate":"2027-03-09","passengers":2,"cabinClass":"economy"}
]
```

Классы: `economy`, `premium_economy`, `business`, `first`. Текущий провайдер поддерживает только взрослых и one-way. Не подменяй неподдерживаемый запрос. Прямой вызов провайдера проверяет поиск, а не авторизацию/UI Check My Flight. Для UI/callable сохраняй штатную bearer-авторизацию и проверку организации; не создавай публичных обходов.

Сначала проверь исходную дату, затем соседние. При отдельном сбое продолжай, пока API доступен. При общей ошибке конфигурации, OAuth, доступа или сети остановись с точной безопасной причиной. При sandbox DNS используй предусмотренную средой эскалацию. Не переключайся на production и не повторяй запросы бесконечно. Не выводи `.env`, секреты, заголовки, полные ответы API. Временные входы/выходы держи в `/tmp`, не коммить их.

Помощник возвращает нормализованные предложения, число вариантов и безопасную диагностику. Catalog rows не равны вариантам. Различай отсутствие зоны, невалидную дату/DST и разрыв маршрута, включая смену аэропорта. Не подставляй UTC и не меняй код проекта без отдельного задания.

## Публичные цены SerpApi

Для публичных цен сначала найди актуальный адаптер `src/lib/flights/serpapi-provider.server.ts` и нормализатор `serpapi-normalizer.ts`, проверь только наличие `SERPAPI_API_KEY` в процессе и локальных env-файлах. Не показывай значение. Если адаптера нет или ключ не настроен, верни конкретный блокер; не заменяй публичный поиск тестовыми Travelport-ценами.

```sh
node .agents/skills/flight-check/scripts/search.mjs /tmp/flight-check-input.json --provider serpapi
```

Используй тот же формат запросов. Существующий адаптер фиксирует `currency=KZT`, `engine=google_flights`, one-way и число взрослых. Другую валюту не обещай без поддержки адаптера. Первый запрос отправь на исходную дату; соседние выполняй только после успешного непустого ответа. Помощник останавливает серию при первом сбое/пустом ответе. Не создавай параллельный поисковый клиент.

Текущий нормализатор SerpApi не сохраняет багаж, продавца, ссылки, booking tokens и evidence полной цены. Поэтому отсутствие этих полей означает «неизвестно», а не «не включено». Пассажиры задаются поиском, но нормализованный результат сам не подтверждает all-passenger total, тариф и сборы. Поле cabinClass также переносится из запроса, а не является независимой проверкой каждого сегмента. Публичную поисковую цену называй «цена агрегатора», сохраняя непроверенный итоговый состав. SerpApi-помощник выводит provenance отдельно от environment: существующий адаптер environment не устанавливает.

Если ответ и текущая интеграция поддерживают получение вариантов бронирования, выбери одного лучшего кандидата среди всех дат и запроси booking options только для него. Не запрашивай токены всех вариантов. Сейчас отдельного метода booking options в интеграции нет: сообщи это ограничение; не называй поисковую цену ценой продавца. Для расширения интеграции сначала прочитай актуальную официальную документацию SerpApi; не угадывай endpoint/параметры. Ссылки и багаж проверяй браузером, если они доступны.

Регрессионный запрос: PVG → NQZ, 2027-01-09 (соседние 08/10 января), 1 взрослый, Economy, KZT; исходная сумма 141323 KZT; ручная кладь 1 × 11 lb (примерно 4,99 кг), сдаваемый багаж неизвестен. Неизвестный вес не удовлетворяет требованию 11 lb. Условные кандидаты с неизвестным багажом перечисляй отдельно от подтверждённо подходящих. Не заявляй экономию до проверки итоговой суммы и нужного багажа у продавца.

## Продавец

Если браузер доступен, открой исходную ссылку и проверь лучших кандидатов по каждой дате у продавца до шага оплаты. При отсутствии offer-ссылки допустим обычный поиск на сайте продавца/авиакомпании. Не создавай фиктивную ссылку конкретного тарифа. Общую страницу поиска обозначай как поиск.

Сверь год, дату, все сегменты/номера, пассажиров, класс, тариф, личную вещь, ручную кладь, сдаваемый багаж и итог за всех с обязательными сборами. Можно выбирать рейсы/тариф; не оформляй бронь/заказ, не оплачивай и не принимай платные услуги. Не вводи придуманные данные пассажиров. Если дальше нужны личные данные, вход или CAPTCHA, останови этот путь и укажи последний видимый этап/цену. Не обходи антибот. При недоступности сообщи HTTP-статус/видимое сообщение. Параметры редиректа — подсказка, не проверенный тариф. Порядок ссылок не доказывает соответствие маршрутам. Не выводи длинные URL с shopping/session-токенами, используй исходную короткую ссылку.

## Результат

Отфильтруй точные аэропорты, локальную дату, класс и пассажиров: ответ может включать ORY вместо CDG или SHA вместо PVG. Другие рейсы, аэропорты и соседние даты показывай как альтернативы. Выбирай самый дешёвый подходящий вариант по каждой дате; неизвестный багаж делает его условным кандидатом. Не угадывай вес/доплаты. Личная вещь не имеет отдельного поля FlightOffer и требует продавца.

Верни по каждой дате число полученных, нормализованных и соответствующих точному запросу вариантов. Таблица: маршрут, дата, все номера рейсов, пересадки/аэропорты, багаж/вес, общая цена за всех, валюта, ссылка и статус цены, время наблюдения.

- **цена у продавца**: реально видна у продавца для указанных пассажиров/тарифа; укажи этап и полноту суммы;
- **цена агрегатора**: production-цена видна только у агрегатора, продавец не подтверждён;
- **тестовая цена**: test/pre-production, не подтверждает доступность покупки.

Неизвестную среду явно пометь непроверенной; не называй её production. Отдельное наблюдение у продавца не меняет происхождение тестовой цены. Если продавец недоступен, укажи, какую цену увидел и где. Пользовательская исходная цена не является вновь подтверждённой ценой продавца.

На исходную дату отдельно оцени совпадение рейса и тарифа: одинакового маршрута недостаточно. Не заявляй подтверждённую экономию по тестовым данным или неполным условиям. Разные валюты не сравнивай без явно указанной конвертации.
